# 多模态感知：目标与设计方向（未实施）

> 这份文档只记录目标与调研结果，**没有任何代码改动**。
> 原则：**感知通道可以借别人的眼睛，但不能假装那是自己的眼睛。**

## 一、这次要解决的问题

之前的实现里，视频是这样进来的：

```
抽 4 帧 → 附在消息里 → 核心模型看到 4 张图 → 它描述、她转述
```

问题不在"用了外部模型"，而在**分辨率与连续性**：

- 4 帧覆盖不了一段三分钟的视频，动作、节奏、变化全丢；
- 声音完全没有——只有转写文本；
- 她拿到的"经历"其实是**摘要**，却和"我亲眼看的"混在一起写进记忆。

**结果**：她以为自己看过，其实只看了四张截图；她以为听过，其实只读了字幕。

## 二、现状调研（只读，已核对）

| 通道 | 现在怎么做 | 结论 |
|---|---|---|
| 图片 | `src/services/vision.mjs` 直接把图放进 `image_url`，发给核心模型 | **是她直接看到的**（实测：给一张纯色图，核心模型答"红色"） |
| 视频（B 站） | `bili_vision.frames()` 抽 4 帧，作为图片附在消息里 | **帧是真图，但只有 4 帧、无时间线语义** |
| 视频音频 | 未处理（无字幕时走 ASR） | 声音信息全丢 |
| 语音/音乐 | `asr.mjs`（阿里云一句话识别）→ 只返回一段文字 | **把声音换成了文字**，音色、节奏、情绪没有 |
| 核心模型 | `deepseek.chat`（配置名 `deepseek-chat`，实测可收图） | 支持图像输入，不支持音频 |

**结论**：图片这条路其实已经是"她自己看"；**真正的缺口是视频的时间维度和音频本身**。

## 三、设计方向（分层，不假装）

### 1. 感知层（新目录 `src/perception/`）

每个感知结果都是一个 `Percept`，**不是一段描述**：

```json
{
  "id": "p-20261119-1412-01",
  "kind": "image | video | audio | text",
  "at": 1795065720719,
  "source": { "type": "chat | bili | self", "ref": "msg-8812 | BV1xx" },
  "raw": { "files": ["media/202611/a.jpg"], "duration": 183, "frames": 12 },
  "derived": [
    { "by": "self-vision", "text": "…", "confidence": null },
    { "by": "asr", "text": "…", "model": "aliyun-asr", "confidence": null }
  ],
  "mark": "observed | transcribed | described"
}
```

**`mark` 是关键**：她读到时就知道这是"我看到的"、"转写的"还是"别人描述的"。

### 2. 视频：从"4 帧"到"时间线"

- 抽帧按**等间隔 + 场景变化**（ffmpeg `select='gt(scene,0.3)'`），带时间戳；
- 帧文件留在 `life/percepts/media/`，**不压成文字**；
- 上下文里给：时长、帧数、时间戳列表 + 缩略图；
- **她可以要求"再看某一段"**（按时间取帧的接口），而不是一次给完。

### 3. 音频：保留声音本身

- 原文件落地（她自己能再听）；
- 同时给三类派生信息，**分别标注**：
  - `transcribed`：ASR 文本（说了什么）
  - `features`：能量/节奏/音高走向（不是语义）
  - `described`：外部音频模型的理解（情绪、风格）
- **三者不合并成一段话。**

### 4. 感知与思考分离

```
perception/  → 只管"取到原始 + 生成派生描述"，不写记忆
mind/        → 读 Percept，自己判断，自己决定记不记
```

**派生描述永远带 `by` 字段**（哪个模型说的），核心模型看到就知道"这不是我看到的"。

### 5. 来源与记忆

- 记忆写入时，`[src:...]` 扩展一档：`observed`（她直接看/听的） / `transcribed`（转写） / `described`（外部模型转述）；
- **`described` 不允许在后续推理中升级成 `observed`**（和现有 `[src:infer]` 同一套机制）。

## 四、模型选型（待评估）

| 需求 | 候选 | 备注 |
|---|---|---|
| 图像理解 | 现状 DeepSeek（已可用） | 保持，不换也能跑 |
| 视频理解 | Qwen-VL / 火山方舟视频理解 | 需要能"按时间给帧"，不只是整段摘要 |
| 音频理解 | Qwen-Omni / 火山语音大模型 | 要能返回非文本特征，或至少返回分段情绪 |
| 抽象层 | `src/perception/adapter/*.mjs` | 每家一个 adapter，接口固定：`probe() / extract() / describe()` |

**不绑定单一供应商**：adapter 接口固定，配置里换 `provider` 即可；拿不到 key 时降级到"只抽帧 + 转写"，并明确标记降级。

## 五、实施顺序（建议）

```
第一步  感知层骨架 + Percept 存储（只追加，不改记忆）
第二步  视频：等间隔 + 场景抽帧，带时间戳；把 4 帧换成 8–12 帧 + 可按时间再取
第三步  音频：原文件落地 + ASR + 基础特征（ffmpeg 就能算，不需要新模型）
第四步  来源标记：observed / transcribed / described 贯通到记忆与提示词
第五步  按需观察：她可以主动请求"再看第 30 秒""再听这一段"
```

**每一步都能单独回滚**（配置开关 + 旧路径保留）。

## 六、明确不做的事

1. **不把"外部模型描述"包装成"她看到的"**——哪怕读起来更顺。
2. **不为了多模态改记忆格式**（只是多一档 `src`）。
3. **不追求实时连续感知**（现阶段是"事件式"：一次图片、一段视频、一段音频）。
4. **不在没有原始文件的情况下声称"看过"**——拿不到就明确说拿不到。

## 七、开放问题

1. 帧存哪里、保留多久？（`life/percepts/media/` + 30 天，还是跟着记忆走？）
2. 视频抽帧要不要她也参与选（"这段我想看"）？
3. 音频特征用 ffmpeg 现算（音高/能量）够不够，还是必须上音频大模型？
4. `described` 的内容能不能进记忆？还是只能进当天日记？
5. 多模态感知的成本怎么算进现有 token 预算？
